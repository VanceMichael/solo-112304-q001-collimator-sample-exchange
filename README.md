# 准直器送样的检具环形缓存与买方签收

检具导出以开机会话区分重复使用的块号。送样检查订单和买方样件编号由交接单登记。

本地来源与合作端均使用合成业务资料。Python 3.11 运行来源服务，服务默认绑定回环地址。

```sh
python3 source_fixture.py --port 8765
python3 -m unittest discover -s tests -v
```

## 数据交换

- `/gauges/index` 返回可导出的分块声明和视为同一轮的副本引用。时间为带时区 ISO 时间，期限右端不包含。
- `/gauges/config` 的配额单位是一份导出原件，设备原件路径接受 GET，同一个请求的重复导出也计一次。配额按指定波次结算。
- `/quality/orders` 记录样件映射、轮次、买方要求的位号、订单优先级和交样截止。deadline 相同时按 priority（数值越小越优先），同级允许任意可交付顺序。
- `/gauges/bases` 中缺项表示该基准尚无定稿。标为 supersedes 的修订与其 applies 列表共同限定影响轮次。坐标系无跨系通用约定。
- `/buyer/intake` 以买方部件位号接收，补齐与更正引用旧回执号。

演练运维端 `GET /__scene` 返回当前时间点，`POST /__scene` 接受 JSON 字段 `index`，从 0 开始顺序切换，每次加 1。换场不会清除合作端当次运行已生成的回执。需要开始新的独立演练时重启服务。业务时间以各来源的当前版本为准。

合作端允许按 `request` 字段查找同路径下的业务请求号，提交使用 `request`、`operation`、`items`（字符串数组）。业务明细使用可选 JSON 对象 `details`，以此请求内的条目编号为键。界面端填多项时按逗号分隔。来源约定的业务动作按下表允许值填写。统一回执含请求号、模拟回执号与各行状态。相同请求号的原样重交返回原回执，参数有变则返回 HTTP 409。回执检索的 404 表示该时刻未查到。描述业务状态的可读来源会随演练进度独立更新，某次提交回执不会提前改写该来源。

## 合作端动作

- `/buyer/intake` 接受 `submit`、`supplement`、`amend`。

## 收件工具（inbox）

质检用 `inbox` 包在导出批次资料前确认每块读数的归属，并在测量块到期前补回缺项：

```sh
python3 -m inbox.cli --origin http://127.0.0.1:8765 --store inbox-state.json run
python3 -m inbox.cli --store inbox-state.json status   # 按交样单查看
```

`run` 依次执行 `sync`（同步来源快照与配额波次）、`collect`（配额内取件）、
`export`（买方导出），也可单独分步执行。行为要点：

- 取件按工厂导出配额运行，按各检测订单的硬交样期限与优先级排序；同一检测组
  优先取可访问期限最近的原件。重试取到同一原件沿用原始出处；同一来源键收到
  内容不同的原件即停用该键，直到检具声明明确哪份有效。
- 上游覆盖某块时改查其他会话的同轮副本；副本缺证或缺口不可恢复时交质检排定
  重测，不再占用其他订单的取件额度；不拿同槽别轮次的读数填缺。
- 基准未入库的读数不外发；基准晚到后按新的导出请求提交。基准被修订追溯取代
  时重新判断已外发项：买方已签收的更正作废（引用旧回执号），被退回的待有效
  读数补件，旧回执及当时依据保留在本地状态文件中。
- 导出请求号由内容决定：同一请求重复运行沿用原回执，资料版本变化即换新号。
  买方只见约定读数与来源标识，检具内部诊断字段留在质检侧。
- `status` 按交样单列出已取、来不及取而需重测、可以签收、仍需补件的位置，
  并追到具体轮次与原件。

演练时按 `POST /__scene` 推进时间点，每个时间点各执行一次 `run` 即可。
